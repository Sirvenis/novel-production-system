# Conditional Stage and Trigger Rules

The pipeline is diagnosis-driven. A manuscript does not automatically receive every possible stage.

## Universal preflight stages

Always run: authority/source lock, manuscript integrity verification, context loading, initial developmental diagnosis.

## Research triggers

Run research/fact verification only when one or more apply:

- medical, nursing, legal, workplace, policing, maritime, aviation, weapons, scientific, or procedural claims affect plot credibility;
- real historical, archaeological, cultural, mythological, religious, or geographic material is used in a way readers may check;
- a factual mistake could harm trust or representation;
- the manuscript's stakes depend on technical plausibility;
- previous review identified likely factual drift.

Night Shift likely triggers medical/procedural verification.
Anunnaki Book 4 likely triggers historical/archaeological/cultural verification only for claims that materially affect reader trust; mythic invention should not be over-policed as textbook accuracy.

## Expansion / developmental revision triggers

Run expansion or structural repair only when diagnosis proves a reader-experience deficit: missing connective tissue, underdeveloped turning point, unclear motivation, excessive summary, abrupt ending, or insufficient genre promise.

Do not expand solely to hit a word count.

## Line edit triggers

Run after structure is stable and only if prose-level issues materially hurt rhythm, clarity, voice, or reader immersion. Avoid homogenising series-specific voice.

## Copy/mechanical edit triggers

Run whenever a manuscript is approaching publication candidate status or after significant editing changes.

## Fresh reader triggers

Run after diagnosis when the central question is reader-experience uncertainty, and after significant approved revisions.

## Stop/escalation triggers

Stop for Andrew / Arden if findings imply canon changes, major rewrite, publication-status change, production model assignment, new paid infrastructure, or conflict between project authority records.


## Diagnostic anti-overediting rule

A diagnosis report is incomplete if it only lists defects. It must identify what is working and should not be changed. Findings with low confidence or plausible intentionality may be logged as watch items, not revision triggers.
